A systems language with a small core

Functions, immutable bindings, explicit mutation, structs, enums, pattern matching, and typed low-level access share one consistent model.

Memory-Safe Systems Model

Ownership, borrowing, non-lexical lifetime analysis, and explicit unsafe boundaries are part of the language rather than library conventions.

Concurrency as a language feature

go blocks, async functions, await, and channels are designed to work with the same type and ownership checks as synchronous code.

Data-parallel foundations

Arrays, tensor-oriented operations, reductions, and the Silicon IR pipeline provide an experimental path to SIMD and accelerator backends.

Direct systems interop

Typed pointers, spans, raw buffers, FFI declarations, and freestanding builds cover the cases where a runtime abstraction is not enough.

A toolchain that explains itself

The compiler, checker, formatter, test runner, documentation generator, LSP, and package tools are documented separately and honestly.

Typed compile-time programming

Strict CTFE, typed reflection, partial evaluation, and structural declaration generation reuse ordinary Vex semantics without token macros or a second runtime model.

Start with the language ​

The guide is organized as a progression rather than a catalogue of isolated features:

  1. Read the introduction to understand Vex's design and the current implementation boundary.
  2. Follow installation to build the compiler and run a first program.
  3. Learn the core language through syntax, variables, functions, and control flow.
  4. Continue with types, enums, ownership, and error handling.
  5. Use the specialist sections for concurrency, SIMD and tensors, GPU and SIR, FFI, and tooling.
  6. Continue with compile-time evaluation and structural declaration generation when you need typed metaprogramming.

Every language example is intended to be small enough to copy into a file. When a feature is not ready for general use, the page labels that fact and points to the relevant limitation instead of presenting a design sketch as production behavior.

Find the right reference ​

  • Language status explains what is verified, experimental, or still planned.
  • Architecture describes the compiler pipeline, runtime, and intermediate representations.
  • Reference documents command behavior for the CLI, test runner, documentation generator, and package tools.
  • Standard library is the API reference generated from the library source.
